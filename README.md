# AI-EnabledCoding

## Setup Command

Please ensure you have the docker app to run these commands:

```bash
docker build -t codemodernizer .
docker run -p 8501:8501 codemodernizer
```

Or, run the streamlit app directly:

```bash
streamlit run home.py
```

## Test Validation Pipeline

Currently, to test the **Validation Pipeline**, build the container if not already built _(this might take a couple minutes)_:

```bash
docker build -t codemodernizer .
```

Then, at this stage, testing of the **full pipeline** can only be done via an **interactive shell** into the container. To start one, run the following :

```bash
docker run -it --entrypoint /bin/bash codemodernizer
```

You will then be inside the container, and should see something similar to the following:

```ruby
root@container:/home#
```

The test script that currently exists lives at the top-level, and is called `_validation_test.py`. If you would like to view the contents of this script, optionally run:

```bash
cat _validation_test.py; echo
```

#### Running Tests

When you run the test script, it expects you to enter a valid `Test<No.>/` directory to test, which lives inside the root-level `/ValidationTest/` folder.

There are currently **five** test folders that exist _(and thus 5 valid inputs when running the test script)_:

<details>
  <summary>Test Folders Explanation</summary>

- `Test1`: contains a single, error-free `test1.c` file.
- `Test2`: contains a slightly modified version of `test1.c`, and should raise a **WARNING**, but no errors.
- `Test3`: contains a slightly modified version of `test1.c`, and should raise an **ERROR** when compilation is attempted.
- `Test4`: contains a project consisting of two source code files, `first.c` and `second.c`, as well as a simple, user-defined header file `second.h`. There should be **no** errors or warnings, and an executable should be successfully generated.
- `Test5`: contains subdirectories in it, and currently serves the purpose of testing Bhargav's **LLM Metrics Stage**.

</details>

To run the test _(from root directory)_:

```bash
python3 _validation_test.py
```

and then enter one of the valid tests from above. Note that tests from the `Test5` directory were created by Bhargav, and while they can be used to test the Compilation and Static Analysis stages, they are _(no more exhaustive)_ than test directories 1-4.

This will output a **JSON dump** of a bunch of stuff. Without going into too much detail, the `ValidationPipeline` goes through and tries to compile `.c` files. If successful in compiling **all** files, it attempts to link the generated object _(`.o`)_ files. It then proceeds to the static analysis stage, where `clang-tidy` is ran on each source code file.

All of this can be found _(and is generated in more detail)_ inside the `compilation` and `static-analysis` subdirectories that are generated within the corresponding `Test<No.>/` directory that was used. Feel free to navigate through the terminal and inspect the files that were generated! Otherwise, for brevity, you can run _(showing `Test1` as an example)_:

```bash
apt-get update && apt-get install tree; tree ValidationTests/Test1/
```

to see what was generated by the pipeline _(change the last command to `/Test<No.>/` depending on which test directory was used)_. You should see the two folders, `compilation` and `static-analysis`, that were generated. You can use the `cat` command followed by the file path if you want to inspect any generated files' contents!
