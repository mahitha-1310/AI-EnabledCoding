# AI-EnabledCoding

## Setup Command

Please ensure you have the docker app to run these commands:

```bash
docker build -t codemodernizer .
docker run -p 8501:8501 codemodernizer
```

Or, run the streamlit app directly:

```bash
streamlit run home.py
```

## Test Validation Pipeline

Navigate to the `feature/StaticAnalysis` branch for a more detailed README on how to test the **Compilation** and **Static Analysis** stages in isolation. The Static Analysis stage has not yet been integrated with this branch (`main`). 

------

Currently, to test the **Validation Pipeline**, build the container _(as above)_:

```bash
docker build -t codemodernizer .
```

Then, at this stage testing of the pipeline can _only_ be done via an **interactive shell** into the container. To start one, run the following:

```bash
docker run -it --entrypoint /bin/bash codemodernizer
```

You will then be inside the container, and should see something similar to the following:

```ruby
root@container:/home#
```

The test script that currently exists lives at the top-level, and is called `_validation_test.py`. If you would like to view the contents of this script, optionally run:

```bash
cat _validation_test.py; echo
```

#### Running Tests

When you run the test script, it expects you to enter a valid `Test<No.>/` directory to test, which lives inside the **root-level** `/ValidationTest/` folder.

There are currently **three** test folders that exist _(and thus 3 valid inputs when running the test script)_:

<details>
  <summary>Test Folders Explanation</summary>

- `Test1`: contains a single, error-free `test1.c` file.
- `Test2`: contains a slightly modified version of `test1.c`, and should raise a **WARNING**, but no errors.
- `Test3`: contains a slightly modified version of `test1.c`, and should raise an **ERROR** when compilation is attempted.

</details>

To run the test _(from root directory)_:

```bash
python3 _validation_test.py
```

and then enter one of the valid tests from above.

This will output a **JSON dump** of a bunch of stuff. Without going into too much detail, the `ValidationPipeline` goes through and tries to compile `.c` files. If successful in compiling **all** files, it attempts to link the generated object _(`.o`)_ files.

All of this can be found _(and is generated in more detail)_ inside the `compilation` subdirectory that is generated within the corresponding `Test<No.>/` directory that was used. Feel free to navigate through the terminal and inspect the files that were generated! Otherwise, for brevity, you can run _(showing `Test1` as an example)_:

```bash
apt install tree
```

and then

```bash
tree ValidationTests/Test1/
```

to see what was generated by the pipeline.
